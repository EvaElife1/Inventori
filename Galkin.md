### Технические решения

`main.py` содержит только меню и ввод-вывод, `inventory.py` — операции с записями; это позволит в спринте 4 вынести работу с JSON в отдельный `storage.py` без переписывания логики. Демонстрационные данные вынесены в константу, чтобы меню и тесты использовали один источник. Уникальность инвентарного номера заложена как правило, проверка появится в спринте 2.

### Статус критериев готовности

- Меню запускается — **да**.
- Демонстрационных записей не менее 5 — **да, 6 записей**.
- Проект открывается из репозитория — **да**.

- Пункты меню добавления, поиска, изменения и удаления пока являются заглушками, это ожидаемо.
- Функция `show_all` принимает список, при переходе на JSON потребуется подгрузка из `storage.py`, интерфейс к этому готов.
- Тесты на заглушки не пишутся.

## Отчёт PO

### Сценарии поиска

**По номеру:**
- Существующий номер → выводится карточка устройства.
- Несуществующий → «Не найдено».
- Пустой ввод → сообщение об ошибке, возврат в меню.
- Регистр не важен (`inv-001` = `INV-001`), пробелы обрезаются.

**По кабинету:**
- Есть техника → список всех единиц кабинета.
- Нет техники → «В кабинете N техника не найдена».
- Пустой ввод → сообщение об ошибке.

### Правила подтверждения удаления

1. Запись не найдена → «Не найдено», удаление не выполняется.
2. Запись найдена → карточка + запрос `Подтвердите (Y/N):`.
3. `Y` → удаление и сохранение в JSON.
4. `N` или пустой ввод → «Удаление отменено».
5. Любой другой ответ → отказ.

### Редактирование

- Поиск по номеру → изменение `room` и `status`.
- Пустой ввод → поле не меняется.
- `status` проверяется по справочнику: `исправно`, `требует ремонта`, `списано`.
- `id` изменить нельзя.

### Приёмочный чек-лист

| № | Проверка | Ожидание |
|---|----------|----------|
| 1 | Поиск по существующему номеру | Карточка устройства |
| 2 | Поиск по несуществующему номеру | «Не найдено» |
| 3 | Поиск с пустым вводом | Сообщение, без падения |
| 4 | Поиск в другом регистре | Находит запись |
| 5 | Поиск по кабинету с техникой | Список единиц |
| 6 | Поиск по кабинету без техники | Сообщение |
| 7 | Изменение кабинета | Сохранено в JSON |
| 8 | Изменение состояния | Сохранено в JSON |
| 9 | Изменение неверного номера | «Не найдено» |
| 10 | Недопустимый `status` | Отказ, не сохранено |
| 11 | Удаление с `Y` | Запись удалена |
| 12 | Удаление с `N` | Запись осталась |
| 13 | Пустое подтверждение | Отказ |
| 14 | Удаление несуществующего номера | «Не найдено» |
| 15 | Повторный поиск после удаления | Не находится |
| 16 | Перезапуск | Изменения сохранены |

### Обновлённые User Stories

- **US-3.1.** Как администратор, хочу искать технику по номеру, чтобы быстро находить устройство.
- **US-3.2.** Как лаборант, хочу видеть технику кабинета для инвентаризации.

- **US-3.4.** Как МОЛ, хочу удалять списанное только после подтверждения.
