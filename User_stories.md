# Система учёта оборудования

## Описание

Приложение на Python для учёта оборудования с хранением данных в JSON-файле.
Реализует просмотр, добавление, поиск, изменение состояния и удаление записей.

---

## 1. Просмотр списка оборудования

**Критерии приёмки:** При выборе соответствующего пункта меню на экран выводится список всех сохранённых записей (сейчас — 5 демонстрационных).

**Пользовательские истории:**
- Как завхоз, я хочу добавлять новое оборудование в систему, чтобы фиксировать новые поступления.
- Как лаборант, я хочу видеть всё оборудование сразу, чтобы понимать, что есть в наличии.

---

## 2. Добавление оборудования

**Критерии приёмки:** Программа запрашивает инвентарный номер, тип, наименование, кабинет и состояние; новая запись сохраняется в памяти.

**Пользовательские истории:**
- Как администратор, я хочу искать технику по инвентарному номеру, чтобы быстро находить пропавшие из виду устройства.
- Как завхоз, я хочу добавлять новую технику, чтобы фиксировать поступления.

---

## 3. Поиск по инвентарному номеру

**Критерии приёмки:** Ввод существующего номера выводит карточку устройства; ввод неизвестного номера выдаёт сообщение «Не найдено».

**Пользовательские истории:**
- Как системный администратор, я хочу изменять статус состояния оборудования, чтобы отмечать технику, требующую ремонта.
- Как администратор, я хочу найти технику по инвентарному номеру, чтобы быстро находить нужное устройство.

---

## 4. Изменение состояния

**Критерии приёмки:** Пользователь может найти запись и изменить поле «состояние» (например, с «исправно» на «требует ремонта»).

**Пользовательские истории:**
- Как материально ответственное лицо, я хочу удалять списанное оборудование, чтобы база данных оставалась актуальной.
- Как системный администратор, я хочу менять состояние, чтобы отмечать технику, которой нужен ремонт.

---

## 5. Удаление записи

**Критерии приёмки:** Удаление происходит только после дополнительного подтверждения пользователя (Y/N).

**Пользовательские истории:**
- Как ИТ-специалист, я хочу, чтобы данные сохранялись при закрытии программы, чтобы не вводить их заново каждый день.

---

## 6. Сохранение данных

**Критерии приёмки:** При перезапуске приложения данные восстанавливаются из файла JSON.

**Пользовательские истории:**
- Как ИТ-специалист, я хочу, чтобы данные не пропадали при закрытии программы, чтобы не вводить всё заново.

---

## Уточнение полей карточки оборудования (PO)

### Поля карточки оборудования

| Поле | Ключ в JSON | Обязательное | Тип | Правила заполнения |
|------|-------------|--------------|-----|--------------------|
| Инвентарный номер | `id` | Да | строка | Уникален во всей базе. Формат: `INV-XXX`, где `XXX` — число. Не может быть пустым. |
| Тип оборудования | `type` | Да | строка | Одно из значений справочника: компьютер, монитор, принтер, проектор, сканер, МФУ, другое. |
| Наименование | `name` | Да | строка | Произвольный текст, 1–100 символов. Не может быть пустым. |
| Кабинет | `room` | Да | строка | Номер кабинета, 1–10 символов (например, `101`, `305А`). |
| Состояние | `status` | Да | строка | Одно из значений: `исправно`, `требует ремонта`, `списано`. |
| Дата поступления | `date` | Нет | строка | Формат `ГГГГ-ММ-ДД`. Если не указана — пустая строка. |
| Ответственное лицо | `owner` | Нет | строка | ФИО, 1–100 символов. Если не указано — пустая строка. |

### Критерии приёмки для полей

1. **Обязательные поля.** При попытке сохранить запись без `id`, `type`, `name`, `room` или `status` выводится сообщение об ошибке, запись не добавляется.
2. **Уникальность `id`.** При попытке добавить запись с уже существующим `id` выводится сообщение «Запись с таким номером уже существует», запись не добавляется.
3. **Формат `id`.** Если `id` не соответствует шаблону `INV-\d+`, выводится сообщение об ошибке, запись не добавляется.
4. **Справочник `type` и `status`.** Если значение `type` или `status` не входит в справочник, выводится сообщение об ошибке, запись не добавляется (либо предлагается выбрать из списка).
5. **Формат `date`.** Если дата указана, она должна соответствовать `ГГГГ-ММ-ДД`; иначе — сообщение об ошибке.
6. **Необязательные поля.** `date` и `owner` могут быть пустыми, запись всё равно сохраняется.
7. **Пустой ввод.** Пустой ввод не завершает программу аварийно, а возвращает пользователя к вводу или в меню.
